SOAP vs REST

Different layers and conventions

SOAP is a messaging protocol with an XML envelope. REST is an architectural style commonly built with HTTP resources and JSON. This project exposes REST for its demo while documenting a SOAP contract.

In this repository

No SOAP exchange happens

The WSDL says SOAP 1.2, document/literal over HTTP. The Java service simulates the decision and returns generated model data through a JSON endpoint.

A Marshaller reads JAXB metadata and writes element names, namespaces, order and values.

05 / Build pipeline

Gradle coordinates. Ant runs XJC.

There is no standalone build.xml. Gradle owns this build; its embedded AntBuilder registers and invokes XJC.

Who does what?
GRADLE

Build orchestrator

Resolves dependencies, models task inputs/outputs, adds generated sources to the Java source set and makes compileJava depend on genJaxb.

APACHE ANT

Task execution API

Ant's XJC task is registered via taskdef, then invoked with schema, output folder and package options. It runs inside Gradle; it is not a second build system here.

XSD input→genJaxb task→Ant + XJC→generated Java→compileJava

06 / Namespace migration

javax and jakarta are distinct types.

The package rename is a binary boundary. Source code may look nearly identical, but classes compiled against one namespace are not assignable to classes from the other.

Legacy JAXB 2.x

javax.xml.bind

Java EE-era API. JAXB was bundled in Java 8 and present as a deprecated module in Java 9/10. Java 11 removed the Java EE modules and tools; later JDKs need explicit dependencies.

import javax.xml.bind.JAXBContext;
import javax.xml.bind.annotation.XmlElement;
Jakarta JAXB 3+/4

jakarta.xml.bind

Jakarta EE namespace after Java EE moved to the Eclipse Foundation. Spring Boot 3 is in the Jakarta generation. This repository uses JAXB API 4.0.2 and RI runtime/tooling 4.0.5.

import jakarta.xml.bind.JAXBContext;
import jakarta.xml.bind.annotation.XmlElement;
Keep each stack internally consistent
Jakarta generated classes→Jakarta JAXB API→Jakarta provider

Avoid mixing generated `javax` classes with a Jakarta-only runtime. Both namespaces can technically load in one JVM, but their `JAXBContext`, annotations and `JAXBElement` types are different and do not interoperate automatically. Migrate dependencies and regenerate sources together. Do not rename every `javax.*`: `javax.xml.datatype` remains Java SE.
